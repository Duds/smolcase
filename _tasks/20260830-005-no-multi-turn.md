### 🐛 [BUG]: Multi-turn conversational thread not maintained
*Origin: Local Testing*

#### 🚨 Current vs. Expected Behaviour
- **Current Behaviour:** Back-and-forth about "working on a project" loses context. The second reply treats "small case" as a new isolated input rather than connecting to the ongoing project discussion.
- **Expected Behaviour:** The LLM builds on previous turns, maintaining coherent thread context across consecutive messages.

#### 🎬 Replication Steps
1. Say "working on a project"
2. As a follow-up, say "project is called small case"
3. Observe the second reply does not connect to the first — it treats the input as a new isolated statement

#### 🎯 Failure Boundary (BDD-style)
- [ ] **Scenario: Regression Verification**
  - **Given:** `GemmaBackend` operating in stateless mode (new `Conversation` per `reply()`)
  - **When:** A follow-up message references prior context from the same session
  - **Then:** The reply treats it as a new, isolated input with no thread awareness
- [ ] **Scenario: Resolution Validation (Fix Verification)**
  - **Given:** `GemmaBackend` injects last 1-2 turns as additional context in the prompt
  - **When:** A follow-up message references prior context
  - **Then:** The reply connects to the ongoing discussion

#### 🔍 Diagnostic & Contextual Data
- **Impacted Subsystems:** `GemmaBackend.kt`, LiteRT-LM `Conversation` lifecycle
- **Error Logs / Stack Traces:**
  ```text
  User: "working on a project"
  LLM: "I have processed the data. What is the required output for this project?"

  User: "project is called small case"
  LLM: "Small case. That is the designation."
  ```
- **Environmental Factors:** GemmaBackend only (stateless by design — single-turn contract)
